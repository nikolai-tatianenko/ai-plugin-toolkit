# CL-021: Reproducible evaluation and architecture records

Status: in-progress
Milestone: v0.1 onward
Dependencies: CL-004, CL-005, CL-008

## Scope

Create synthetic human-reviewed cases, baseline runners, metrics, and architecture decision records.

## Acceptance criteria

- Report model/config/dataset versions, total background-inclusive cost, latency, correctness and failures; publish no invented savings.
- Record verification commands/results and relevant source or build revision.
- Document unsupported cases and remaining work; do not mark verified from mocks alone.

## Evidence

Branch `claude/busy-thompson-avly5w` (single v0.1 PR, stacked on CL-001/CL-002). Environment: Linux, Node 22.23.4, pnpm 10.28.0, SQLite 3.53.4 via `node:sqlite`. Full suite: `pnpm install --frozen-lockfile && pnpm build && pnpm test` → 192 passed, 3 skipped (opt-in live Claude test; two real-Beads suites), green in a fresh clone and on repeated runs. GitHub Actions has not run (account billing limit), and Node 24 was not tested locally.

Changed paths: `apps/eval/**`, `eval/datasets/extraction-v1/**`, `docs/adr/0004`–`0007`.

- Harness `pnpm eval` reports precision/recall by span overlap and type, unsupported-claim rate, current-decision accuracy, accepted/rejected counts, tokens, cost (unknown stays unknown), latency, harness/prompt/dataset versions and limitations.
- Dataset: 3 synthetic cases with annotations (kickoff, a decision correction, a build log with prompt injection).
- Fixture run (reproducible, `apps/eval/test/harness.test.ts`): precision 11/12, recall 11/14, unsupported 1/12 (the injected "all tests passed" claim), current-decision accuracy 2/2. These numbers describe the hand-written fixture, **not a model**.
- ADRs added for routing, the extraction lifecycle, acceptance states and sync ownership.

## Limitations and remaining work

- Annotations are not yet reviewed by a person.
- No live model run, and no full-history or retrieval baselines; no comparative or savings figure exists.
- Thresholds are not chosen (the test plan requires a baseline first).
